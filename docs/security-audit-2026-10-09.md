# 2026-10-09 安全审查

审查范围：管理与服务登录、全部管理 API、配置和凭据持久化、反代与 WebSocket、IP 防火墙/Coraza/冻结、图片上传导入、内网扫描、DDNS/证书/订阅、日志、备份恢复、更新及启动器、安装与 Docker 配置，以及管理前端的动态 HTML 和 URL 输出。检查源码、模拟请求和依赖调用路径，没有对公网运行实例进行破坏性渗透。

## 已修复

1. **管理员会话跨业务后端泄漏**：原反代只过滤独立服务验证 Cookie。当管理与业务入口共用主机名时，浏览器发送的管理员 Cookie 可能到达业务后端，后端也能返回同名 Cookie。普通业务后端现在既不能收到也不能设置管理 Cookie。仅明确指向本机 `127.0.0.1` / `::1` 的实际管理端口的反代保留管理会话；独立服务验证 Cookie 仍统一过滤。用模拟恶意后端验证多个 Cookie 头、重复 Cookie、正常业务 Cookie 和管理页反代登录保存。
2. **全局登录限流可被单个来源耗尽**：改为连接来源 IP 独立的每分钟 8 次限制，并将同时验证限制为 2 个、来源记录限制为 1024 个。忽略伪造的转发来源头。验证攻击来源不能耗尽另一来源的登录额度。
3. **管理读取接口的来源校验不足**：所有鉴权处理现在同时拒绝未允许的 Origin 和浏览器明确标记的跨站请求；允许配置的公网管理地址继续工作。无 Origin 的本机工具仍必须提供有效会话。
4. **慢速 JSON 请求无读取截止时间**：设置 15 秒的读取截止时间并在处理后复原，防止登录请求无限期占用验证名额。

## 验证与结论

- 扩展全部端点无会话/伪造会话测试，包含在线更新、后台进度、扫描与图标。测试注入字符串、严格 JSON、路径和方法混淆、失效会话、重启后会话、跨站请求及配置不变。
- 现有备份 AES-GCM 完整性、ZIP 路径/解压大小/架构/哈希校验，日志脱敏、图片重编码与恶意 HTML 转义测试继续执行。
- Linux amd64 的 `govulncheck` 调用路径扫描没有发现已知可达漏洞。模块级提示 `GO-2026-5932` 涉及未使用的 `golang.org/x/crypto/openpgp`，项目不导入或调用该包；不应将整个 crypto 模块移除，因为密码验证和加密备份使用其中受支持的包。工具说明：[Go Vulnerability Management](https://go.dev/doc/security/vuln/)，公告：[GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932)。
- 检查范围内未发现无需管理密码即可直接读取、修改管理配置的入口；会话泄漏问题可能导致攻击者窃取已登录会话后接管，因此已修复。此结论限定于当前源码和测试，不能证明不存在未知漏洞。

## 现有边界

管理员被授权选择内网反代后端、扫描内网地址和导入内网图片，因此这些已鉴权能力可以访问内网，不能作为公开 API 使用。在线更新使用 GitHub HTTPS 与发布哈希验证完整性，没有独立的发布者签名。公网管理应使用独立域名和 HTTPS；直接 HTTP 登录的会话依赖可信网络。主机 root 权限或已泄漏的管理密码不属于鉴权绕过保护范围。

## 0.0.24 兼容性修复

0.0.23 的回环地址识别遗漏了本机网卡地址，反代填写服务器内网 IP 时会过滤管理 Cookie。现在仅对回环地址、localhost 或当前本机网卡的 IP，加实际管理端口，保留管理会话。任意其他 IP、域名和端口仍按普通业务后端隔离，不根据 DNS 或转发头放宽信任。已验证通过网卡 IPv4 地址反代的 HTTPS 登录、配置读取/保存、无会话拒绝和安全 Cookie 属性；IPv6 与非管理目标通过分类测试。
