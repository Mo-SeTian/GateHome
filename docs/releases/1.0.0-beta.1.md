# GateHome v1.0.0-beta.1 测试版

Aurora Next 新控制台已完成迁移：登录、账户与两组 17 个功能页面接入原有 Go API，前端、字体和 SunPanel 资源随单个 Go 二进制分发。

- 默认管理入口 `/` 跳转 `/console/`，原版保留 `/legacy/`，设置页可切换。
- 反代、TCP/UDP 转发、防火墙、IP/CIDR 规则订阅、DDNS、证书、日志、统计、首页、MCP、备份、更新和设置均沿用原有业务及存储。
- 概览补齐全部 14 个组件，支持显示选择、拖拽/键盘排序、采集网卡及地图省份；布局保存后跨重启保留。
- 保留原管理员账号密码、配置、凭据、证书、日志、历史流量和首页数据库，无需重新初始化。

## 安装与更新

这是 GitHub **Pre-release**。在现有控制台的「更新」选择「Beta 测试版」，检查后安装 `v1.0.0-beta.1`。检查结果可能缓存 5 分钟，请按页面的下次检查时间重试。离线更新可上传 `gatehouse-1.0.0-beta.1-update.zip`。

本机迁移验收实例已运行 `1.0.0`，版本排序高于本测试版，更新器会正常拒绝降级；它无需再次安装 Beta 包。已有较早的正式版或 Beta 版本可更新到本版本。

| 附件 | 用途 |
| --- | --- |
| `gatehome-linux-amd64.tar.gz` | Linux x86_64 完整安装包，包含启动器安装脚本及 systemd 服务 |
| `gatehome-linux-arm64.tar.gz` | Linux ARM64 完整安装包 |
| `gatehouse-1.0.0-beta.1-update.zip` | 网页/在线更新包，包含两种 Linux 架构 |
| `gatehome-SHA256SUMS` | 上述三个包的 SHA-256 校验清单 |

升级前停服保存 `config`、`log`、`data`、`sunpanel` 四个完整目录，尤其保留 `data/route-traffic`。网页备份 ZIP 和历史更新快照不含历史流量，完整迁机或完整历史回退使用四目录副本。已有数据升级不要运行 `init`。

Docker 用户继续保留四个持久化挂载；网页 ZIP 更新替换业务程序，若要同时升级容器内启动器，使用本标签源码重新构建镜像。回滚会恢复备份时的程序、配置和账户，请先保存当前数据。

## 验证范围

已完成 17 页带数据及空数据场景、桌面/手机与双主题、布局保存和并发冲突、真实转发及重启、独立首页账号隔离、MCP 鉴权、加密备份和 WebDAV 验证。完整数据副本实际升级、回滚和再升级后，原账号、配置、证书、日志、历史流量及首页数据保持一致。

迁移验收通过 29 项前端自动测试、Go 全量测试与 `go vet`、原版 12 组检查、干净源码构建和 Linux 双架构打包。公网 DNS 和 CA 签发需要目标环境的真实域名、凭据和网络；本机模拟数据与凭据不随发布包分发。

更多说明见 [迁移交接](../aurora-next-1.0.0-handover.md) 和 [验收清单](../aurora-next-migration-checklist.md)。
