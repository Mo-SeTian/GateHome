# GateHome 1.0.0-beta.14

本次预发行版本（Pre-release）核心重构了解耦日志与系统快照的架构逻辑，彻底解决了高日志量场景下更新回滚快照容量超限（64 MiB 上限）阻断系统更新的痛点，并优化了备份与容量预检的前端体验。

## 主要更新与改进

### 1. 更新回滚快照与日志文件彻底解耦
- **更新快照排除日志**：更新回滚快照与打包备份逻辑中默认排除 `logs/` 目录，更新快照仅打包配置、证书、首页应用数据库、自定义图片与订阅缓存；
- **日志持久保留在磁盘**：日志文件（`calls.jsonl` 等）原地持久保存在服务器磁盘上，不受系统更新、升级失败回滚或常规快照操作的任何干扰；
- **解决更新容量阻断瓶颈**：彻底摆脱日志积累（如数十兆乃至上百兆访问日志及 Base64 编码开销）逼近并超出 64 MiB 保护上限的问题，系统在线更新再无阻碍。

### 2. 还原与回滚的安全隔离与向后兼容
- **回滚操作不碰日志目录**：还原与回滚操作增加日志文件检测，若快照不含日志，完全不触碰磁盘日志目录，绝不会重命名或清理现存业务与安全日志；
- **向后兼容旧备份包**：若导入以前包含日志的旧版备份包，恢复引擎依然可安全向后兼容还原历史日志并由日志模块正确打开。

### 3. 容量预检（Capacity Inspection）与前端体验升级
- **日志容量透明独立展示**：`inspectBackupCapacity` 继续精准统计服务器现存日志文件总大小（`c.LogBytes`）返回前端，但不再计入快照体积与 64 MiB 限额；
- **前端直观标识**：设置页面的「备份与更新容量预检」卡片中，日志明确标识为「**日志 xx MiB（磁盘保留）**」，并在说明栏明确告知用户日志原地保留在磁盘中不占快照配额，快照仅包含配置、证书与核心数据。
