# GateHome 前端迁移复核（2026-11-10）

> **后续修复：`1.0.0-beta.9`** 已修复下方 1–6 项问题，并补回显式密码清除、对应路由流量入口、发现服务名称/图片选项及旧版默认协议/冻结时长。新增的浏览器回归实际验证普通 HTTP 下的新增、保存、发现服务与键盘操作。下文保留 beta.8 审查时的事实；版本修复详情见 [发行说明](releases/1.0.0-beta.9.md)。轮询集中化和整体 CSS 收敛作为后续性能工作，本次未引入业务模型重构。

## 结论与当前进度

审查基线为 `main` 的 `4db16a1`（`1.0.0-beta.8`），对照仓库仍保留的原版控制台 `internal/gateway/web/` 和实际 Go Handler、配置模型。登录、账户及 17 个业务页面已迁移，Go 嵌入、构建与核心 API 链路可运行；但存在可复现的兼容性缺陷及若干旧版功能差异，暂不宜把“迁移完成”理解为“行为完全一致、无需继续回归”。

优先修复普通 HTTP 下无法新增配置，再补齐路由域名/协议与服务发现策略语义，之后处理命令面板和旧版操作入口。无需为这些问题重写 Go 数据模型或迁移数据库。

当前版本存在三个不同状态：

| 对象 | 实测状态 |
| --- | --- |
| `main` / `origin/main` | `4db16a1`，`1.0.0-beta.8` |
| `develop` / `origin/develop` | `824ce9a`，`1.0.0-beta.1`，比 main 少 7 个提交 |
| 本机主容器 `gatehome-newui-gatehouse-1` | 程序实际版本仍为 `1.0.0`，健康检查正常 |

最近 beta.2–8 的差异集中于 Vue 页面、组件和 CSS，没有更改 Go API 或数据模型。本轮在 `/Volumes/Ti600/GateHomeNewUI/review-beta8` 和 `review-beta8-empty` 建立隔离副本，以当前代码构建的 `beta.8` 单二进制验证；未替换主实例程序，未重置原账号或修改生产业务配置。

## 已确认的问题

### 1. P1：普通局域网 HTTP 下，多处新增功能直接失效

新版在反代路由、反代组、端口转发、订阅、DDNS、证书、防火墙及服务发现导入中直接调用 `crypto.randomUUID()`。该 API 在普通非本机 HTTP 源不可用。

实测用 `http://gatehome-review.test:17672` 映射到隔离服务，浏览器报告 `isSecureContext=false`、`typeof crypto.randomUUID='undefined'`。点击新增反代组、反代服务、转发、订阅、DDNS、证书、防火墙，均没有打开对应弹窗，Vue 控制台记录 `TypeError: crypto.randomUUID is not a function`。这不是 Go API 拒绝，错误发生在发送请求之前。同一源的旧版可以正常打开新增弹窗并生成 UUID。

位置：`frontend/src/views/RoutesView.vue:629`、`:706`，`ForwardsView.vue:253`，`SubscriptionsView.vue:259`；`frontend/src/components/DdnsEditor.vue:127`、`CertificateEditor.vue:125`、`FirewallEditor.vue:417`、`ServiceDiscovery.vue:159`。旧版实现位于 `internal/gateway/web/app.js:6`，使用支持普通 HTTP 的 `crypto.getRandomValues()` 生成 UUID。

建议：复用旧版算法作为兼容生成函数，保留安全随机数来源；为普通 HTTP 和 HTTPS/localhost 分别加入浏览器新增操作测试。不能仅用 localhost 验收，这正是当前 29 项测试未覆盖的环境差异。

### 2. P2：服务发现导入无法选择防火墙，创建结果固定不关联策略

旧版发现服务表单可选择防火墙，导入函数将选择值写入新路由。新版没有该选项，`frontend/src/components/ServiceDiscovery.vue:167` 固定写入 `firewall_id: ''`。

本轮在隔离环境实际扫描本机 HTTP 上游、选择并导入一条路由，确认表单无防火墙选择，保存后的路由防火墙 ID 为空；测试后已恢复原配置。若用户希望导入时即应用来源限制，新版需要逐条再编辑，在启用组时可能遗漏策略。

建议：恢复批量导入的防火墙选择，并明确显示不关联策略的含义。另有两个次要差异：旧版允许编辑发现服务的名称和选择是否使用图片；新版使用扫描名称并自动导入图标。旧版对不受信任的 HTTPS 上游会阻止导入，新版只提示但仍可创建，实际回源可能失败。应明确这些变化是否为产品决定。

旧版参考：`internal/gateway/web/index.html:74`、`internal/gateway/web/app.js:1192`；新版参考：`ServiceDiscovery.vue:35`、`:149`。

### 3. P2：多级子域名前缀的补全与旧版不一致

`frontend/src/api/configuration.js:8` 将所有含 `.` 的输入直接当作完整域名。反代组后缀为 `example.com` 时：

| 输入 | 旧版补全 | 新版补全 |
| --- | --- | --- |
| `@` | `example.com` | `example.com` |
| `nas` | `nas.example.com` | `nas.example.com` |
| `app.home` | `app.home.example.com` | `app.home` |
| `app.home.example.com` | 原样保留 | 原样保留 |

已对旧、新函数分别执行相同输入，并在新版实际表单中确认显示“保存为 app.home”。新结果可能被后端视为合法的另一个域名，形成错误路由；绑定 DDNS Zone 时也可能被范围校验拒绝。服务发现复用该函数，同样受影响。

建议：明确区分“子域名前缀”和“完整域名”模式，保留已有完整域名的编辑兼容性；补充嵌套前缀回归。不要简单把所有带点输入都视为完整域名。

旧版参考：`internal/gateway/web/app.js:1156`；新版表单：`frontend/src/views/RoutesView.vue:213`。

### 4. P2：新路由默认协议从按组选择 HTTPS 变为固定 HTTP

旧版在所属组配置 HTTPS 端口时默认勾选 HTTPS；新版创建记录固定 `tls: false`（`frontend/src/views/RoutesView.vue:636`），服务发现也默认未勾选 HTTPS（`ServiceDiscovery.vue:83`）。

同一组配置、同一后台，实际打开旧新版新建路由弹窗，旧版 TLS 为 `true`，新版为 `false`。若组只监听 HTTPS，新版默认表单保存会因没有 HTTP 端口而被后端拒绝；若两者都开，则默认暴露协议发生变化。后端限制仍然存在，没有被前端绕过。

建议：沿用旧版按组选择协议的默认值；切换所属组时处理协议可用性，避免把无 HTTP 监听的组默认设为 HTTP。旧版参考 `internal/gateway/web/app.js:1376`，后端约束 `internal/gateway/config.go:893`。

### 5. P2：命令面板过滤后选中索引没有复位

面板只在打开时重设 `selectedIndex`，输入条件变化后未重置或约束索引。复现：打开面板，向下移动 10 项，搜索“概览”，再按 Enter。列表只剩一个结果，却没有选中项，仍停留原页面、面板未关闭。

位置：`frontend/src/components/CmdkModal.vue:155`、`:172`。

建议：查询或结果集合变化时复位/约束索引；键盘移动时让选中项滚动到可视区域，并覆盖“先移动、再搜索、再确认”的测试。

### 6. P2：命令面板的模态声明没有对应的键盘边界

面板用普通 `div` 声明 `role="dialog" aria-modal="true"`，没有焦点约束、背景 inert 或关闭后焦点恢复。实际按 Tab，两次后焦点离开面板，随后落到背景侧栏链接；此时仍显示模态遮罩，可以误操作被遮挡页面。

位置：`frontend/src/components/CmdkModal.vue:4`。此外全局 `frontend/src/styles/main.css:55` 清除了按钮 outline，部分自绘复选框也没有对应 `:focus-visible` 提示，应一起检查。

建议：优先与现有编辑器一致使用原生 `dialog.showModal()`，或完整实现焦点约束和恢复；保留明确的键盘焦点样式。手机侧栏也建议补 Escape、焦点恢复及关闭按钮可访问名称（`Sidebar.vue:34`）。

## 其他明确的旧新版差异

| 功能 | 旧版 | 新版 | 判断 |
| --- | --- | --- | --- |
| 反代独立访问密码 | 关闭验证后可显式清除已保存密码 | 仅能保留/重设，没有清除操作；关闭验证不会主动清除哈希 | 功能缺口，建议补齐。旧版 `app.js:1507`；新版 `RoutesView.vue:681` |
| 路由流量入口 | 服务菜单直接“查看流量”，带入对应路由 | 流量页可选择规则，但反代卡片没有快捷入口，流量页也未接收路由查询参数 | 操作路径退化，统计能力本身仍在 |
| 账号失败冻结默认值 | 新建及缺省值按 60 分钟展示 | 新建及缺省值按 30 分钟展示 | 行为默认值不同，应确认并统一；已有显式时长仍保留 |
| 概览与首页 | 传统工作台 | 新组件布局、双主题、更多状态说明；SunPanel 继续独立登录 | 展示变化，未发现数据模型替换 |
| 登录与维护 | Go Cookie，会话失效后重新登录 | 同一机制；新版补充路由回跳和任务反馈 | 主要语义一致 |

反代密码清除和流量入口不是数据库能力丢失，接口与后端处理仍在；问题在新版没有提供相同的操作路径。不要将“尚无界面入口”误判为“旧数据无法保留”。

## 本轮验证证据与边界

- 前端 29 项自动测试与 Vite 生产构建通过；原生 macOS arm64 单二进制构建并启动成功，版本为 `1.0.0-beta.8`。
- Docker Linux 环境对当前工作区执行 `CGO_ENABLED=0 go test ./... -count=1` 及 `go vet ./...`，全部通过。本轮未把此结果表述为 `-race` 测试；发布工作流仍包含 race。
- 原版 12 组专项脚本通过。这些主要检查旧版代码，不能据此推断新 Vue 组件的全部交互正确。
- 带数据、空数据各 17 页，桌面 1440px/手机 390px 检查通过，未见持续横向溢出或普通加载时的未捕获异常；抽样查看双主题截图。没有把“页面标题可加载”当作“整页所有操作已验证”。
- 浏览器复现普通 HTTP 新增失败、命令面板索引和焦点问题、域名预览与 TLS 默认值差异。另实际完成本地发现服务扫描/导入、临时转发创建及并发冲突，写入后恢复测试配置。
- 使用的账号密码从本机钥匙串读入进程，不回显、不写入报告。审查材料和截图位于项目忽略目录 `.local/review-beta8/`，模拟数据位于上述独立运行目录。
- Go 业务测试覆盖了相关核心行为，但本轮没有重新实施公网 DNS/CA 操作、真实第三方 WebDAV 兼容性测试、长时间大流量压测，以及逐一覆盖式恢复/更新。前期迁移演练记录保留在原验收清单中。

## 建议执行顺序

1. **兼容性修复**：集中修复 UUID 生成，加入真实非安全 HTTP 源的新增配置回归；确认全部新增表单恢复可用。
2. **路由语义对齐**：处理嵌套前缀、完整域名编辑、按组选择 TLS、服务发现导入防火墙，以及密码清除/流量快捷入口；用同一组输入对比旧新版保存结果。
3. **键盘与反馈修复**：命令面板结果复位、可视滚动、焦点边界/恢复、按钮与复选框焦点样式；测试键盘和触屏。
4. **补上持久回归**：把本轮关键复现加入仓库自动化，覆盖 HTTP/HTTPS、空/有数据、revision 冲突及后台任务。现有 29 项以 API 辅助函数为主，无法发现这些 Vue 交互问题。
5. **分支和运行环境对齐**：先同步 main 中 beta.2–8 的改动到 develop，再按修复版本构建并在保留四目录备份的前提下更新本机服务，核对程序实际版本。本轮不自动同步或发版。
6. **性能与样式收敛**：App 每 10 秒和多个页面每 5 秒会重复读取状态，可集中轮询、限制慢请求重叠并在页面不可见时暂停；后续减少全局样式高优先级覆盖。先测请求数量/耗时和多宽度截图，再做局部调整，无需整体重写。

审查阶段仅新增本审查文档；用户随后授权的修复与预发行工作记录在文首及对应发行说明中。
