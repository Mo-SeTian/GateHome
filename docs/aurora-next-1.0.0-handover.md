# GateHome Aurora Next 1.0.0 迁移交接

## 完成范围

迁移分支为 `develop`，版本从 `0.9.0` 升为 `1.0.0`。登录、账户操作和两组 17 个功能页面均已接入原有 Go API；概览补齐原版全部 14 个组件及布局配置，命令面板 DDNS 同步使用真实任务接口。逐页功能和各阶段验证见[迁移验收清单](aurora-next-migration-checklist.md)。

Vite 产物通过 `frontend/embed.go` 的 `//go:embed all:dist` 嵌入 Go 二进制。运行时无需 Node.js、独立 Vite 服务或源码目录；字体随二进制分发，继续使用管理端严格 CSP。Go 业务模型和 SQLite 数据结构沿用原实现。

| 入口 | 1.0.0 行为 |
| --- | --- |
| `/` | 临时重定向至 `/console/` |
| `/console/` | Aurora Next 控制台，页面使用 `#/overview` 等哈希路径 |
| `/legacy/` | 原版控制台；新版设置页提供链接 |
| `/api/`、`/sunpanel/`、`/mcp` | 沿用原接口及各自鉴权规则 |

两套管理界面共享管理员账户、会话和业务数据；SunPanel 继续使用独立账户。旧版书签可改成 `/legacy/#routes`，新版对应 `/console/#/routes`。进入旧界面仅切换操作界面，不恢复历史配置或程序。

## 数据保留与升级

本次保留原有管理员密码及凭据，不需要重新初始化。升级前停服，完整复制以下四个目录，并保留可运行的旧程序或镜像：

| 目录 | 必须保留的内容 |
| --- | --- |
| `config` | 账户、业务配置、凭据和备份设置 |
| `log` | 当前及轮转的项目、访问与安全日志 |
| `data` | 证书、服务图片、订阅缓存、维护数据及 `route-traffic` 历史流量 |
| `sunpanel` | 首页数据库、用户、分组、网站及其资源 |

应复制整个目录，而非仅复制数据库文件。容器部署须保证这些路径仍挂载到相同位置并具有正确读写权限。启动新版后重新登录，核对版本、配置、证书、监听与首页。**已有数据升级不要执行 `init`**；该命令仅用于新实例或有意重置管理账户。

网页备份 ZIP 和历史更新快照按原有后端范围工作，**不包含 `data/route-traffic`**。需要完整迁机或完整历史回退时，使用停服后的四目录副本。

回退方式：界面使用问题可直接进入 `/legacy/`；程序问题可在更新页选择升级前版本并确认恢复。历史版本恢复会回到备份时的配置和账户，之后的改动可能丢失，操作前先留存当前四目录。若需要恢复所有历史流量，应停服，配套恢复旧程序及完整四目录副本，不混用不同时间点的文件。

本机已用独立副本完成正式 ZIP 的 `0.9.0 → 1.0.0 → 0.9.0 → 1.0.0` 实际安装、回滚及再次升级，逐次核对原账号、完整配置、凭据标志、证书、首页用户、历史日志 ID 和固定时间窗流量。主实例升级前也保存了完整快照；升级后核对原凭据哈希、证书文件摘要和首页数据库记录保持一致。

## 构建与验证

从仓库根目录执行：

```sh
make build        # 构建三套前端并编译当前平台单二进制
make test         # 前端测试、Go race 测试及 go vet
make release      # Linux amd64/arm64 二进制和校验过的更新/安装包
```

构建需 Go 及 Node.js 22.13+。直接 `go build` 前必须先生成嵌入资源；直接 `npm run build` 后还需重新编译 Go。Dockerfile 和 Makefile 已包含完整前端构建链。

第十步验证结果：

- 前端 29 项自动测试、生产构建、Go 全量测试与 `go vet`、原版 12 组静态检查通过。Go 全量测试在 Linux Docker 环境运行；本机 CGO 禁用构建及 Linux 双架构编译通过。
- 干净源码副本不含依赖或生成资源，完整构建成功；发布 ZIP 的清单、版本、平台与逐文件 SHA-256 均已验证。
- 有数据与独立空数据实例全部 17 页可用；桌面侧栏、命令面板键盘、手机抽屉、双主题及空/失败反馈通过。概览拖拽与键盘排序、隐藏全部、冲突草稿和重启持久化通过。
- 主实例验证实际转发增删改、首页独立登录与原数据、MCP 鉴权隔离、加密备份下载/上传预检和 WebDAV 目录；重启后 TLS、双栈 IP 检测、TCP/UDP/双协议回显及数据保留通过。
- 资源和字体同源，无 CSP 违规或浏览器未捕获错误。根入口、新版入口及旧版回退登录通过。

公网 DNS 写入和公网 CA 签发仍需在目标环境配置真实域名、凭据与网络；本机验证使用模拟托管商及测试 CA，模拟成功不等同于公网签发。迁移交付之后，发布阶段将 `develop` 合并到 `main`，测试发行版使用 `v1.0.0-beta.3` 及匹配的程序版本，以兼容既有 Beta 更新渠道；详见 [测试版发行说明](releases/1.0.0-beta.3.md)。本机已验收的 `1.0.0` 主实例与原安装产物继续保留。
