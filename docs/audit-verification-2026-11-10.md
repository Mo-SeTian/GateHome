| STB-4 | 授权范围选择，与 SEC-2 重叠 | `admin_access`、`firewalls` 明确属于当前配置修改工具可操作分区，仍需有效 Token、write、revision 和正常配置校验，不是未授权写入。可以设计独立安全策略权限，但把配置修改简单等同维护会改变已有授权契约；与 SEC-2 一并评估，建议 P2。 |
| STB-5 | 冷却体验事实成立，自动频率推论不符 | 同一任务 5 分钟冷却会挡住修正凭据后的立即申请；但自动检查 ticker 为 **1 小时**，不是每 5 分钟自动申请。保存配置或人工触发可能增加尝试。CA 限额按账号和 identifier 计算，也不是所有失败都算一次授权失败。建议 P3 显示剩余冷却、区分错误和遵守 CA 重试时间；不要无条件重置冷却。 |
| STB-6 | **检测覆盖限制成立，既有告警与文档已说明** | 仅记录模式超限提前返回，不再做正文 CRS 检查，甚至不会输出此前 transaction 累积的具体规则；但明确记录规则 1002“未完成内容检查”，完整正文继续转发。隔离攻击前缀测试复现：小正文有 CRS 命中，大正文仅有 1002。拦截模式仍返回 413，不是该模式的绕过。可以按 P2 改进受限前缀检测，但不得将部分检查标成完整安全结论，也要保留完整回源正文。 |
| STB-7 | 特定拓扑风险成立，Docker 概括和豁免建议不当 | 网关以实际连接 IP 计数/冻结；当前置代理或某种 NAT 拓扑聚合来源时，使用同一代理来源的同一路由用户会连带受影响。并非所有 Docker bridge 都丢失来源，也不是冻结后宿主机所有网络都停止。可信代理可作为 P2 部署能力设计；不能把所有私网与回环自动豁免，否则内网攻击和实际代理来源可能不再受防护。 |
| STB-8 | **符合当前发布契约，非现有更新故障** | `release.yml` 监听 `v*`，发布前校验 tag 必须等于 `v` + VERSION，分支发布也生成带 v 的 tag。在线更新与之匹配；不带 v 的第三方标签不属于当前发布规范。无须为不存在的当前发行格式差异提高到 P2。 |
| STB-9 | 停顿事实成立，是一致性备份的取舍 | snapshot 持锁、停子进程、复制数据、重启并等待就绪；新 Sun-Panel/MCP 请求获取同一锁会等待。15 秒是健康检查等待窗口，不是备份全过程上限；文件复制和进程停止也耗时。建议 P3 评估显式维护状态与快速反馈，不能只把解锁搬到启动中途而忽略并发停止、重启和快照一致性。 |
| OPT-1 | 容量淘汰体验成立 | 先清理过期会话，仍满时按 map 迭代删除一项，可能删除活跃会话。需要已经成功登录才能创建这些会话。优先淘汰最早过期项即可改善，建议 P3，无需立即引入完整 LRU。 |
| OPT-2 | 串行延迟成立，**不是无界队列雪崩** | ddnsLoop 串行执行组；慢组会延迟后续组和手动任务。但触发队列容量 100，满时拒绝入队，不能描述为无界积压。建议 P3 先量测，再采用有上限的并发、同组去重及取消机制，避免每组无限启动协程。 |
| OPT-3 | **报告所称字段写入竞态不成立** | 两协程分别写 IPv4/IPv4Error 和 IPv6/IPv6Error，没有写同一字段；`WaitGroup.Wait()` 后才合并发布，cache 更新另持锁。3 项 DNS 回归在 Linux Go 1.27.1 下 `-race -count=100` 全部通过。不能将“同一结构体”直接当作“同一内存位置”。 |

## 不应直接照搬的建议

1. STB-3 的非零才覆盖会将全局 Sun-Panel 账号权限授予本应未绑定的独立客户端。
2. SEC-4 的容量满即无条件放行会削弱限速，先应清理过期状态并明确容量分配、观测和降级策略。
3. STB-7 的全部 RFC1918/回环豁免会扩大免检来源，可信代理应按显式连接来源和明确头部链配置。
4. STB-1 静默跳过路由会隐藏配置错误；STB-9 简单缩小启动锁范围可能破坏进程生命周期和备份一致性。

## 历史问题中仍需保留的边界

`security-audit-0.0.8.md` 的同主机名不同端口 Cookie 问题有两个场景：

- 经过 GateHome 普通业务回源的 Cookie：已由请求与响应过滤处理，现有回归通过。
- 浏览器直接访问同主机名其他端口的不可信服务：没有经过网关过滤，仍可能接收管理 Cookie。隔离测试用两个本机临时 HTTP 服务器复现自动携带，并确认收到的会话可以读取临时管理配置；没有打印或保存令牌值，也没有访问真实服务。

因此专用管理主机名与 HTTPS 的部署要求仍适用，不能仅靠不同端口隔离管理员会话。同样，直连明文 HTTP 仍依赖可信网络；本轮没有检查真实部署的公网映射和 TLS。

旧版前端退出后隐藏 DOM 的问题不能原样套用到当前 Vue：现在退出会卸载应用界面、停止 App 轮询、取消其请求并重置共享配置/状态。这里只核验明确代码路径，没有声称浏览器堆内存会被物理擦除。

## 新报告遗漏的当前差异

**图片格式提示与实际能力不一致，建议 P3 修正。** `RouteImagePicker.vue:29`、`:35` 和底部提示宣称支持 SVG，后端 `route_images.go:43` 只接受 PNG/JPEG/GIF/WebP/ICO。使用无脚本的最小 SVG 调用真实上传 Handler，返回 400 和支持格式错误。最小修复是前端移除 SVG 宣称并补齐 GIF 提示；若要新增 SVG 能力，需要单独设计安全处理，不能只放宽 MIME。

此外，beta.8 复核已指出但尚未收尾的状态轮询重复仍存在：App 每 10 秒，部分页面每 5 秒调用状态类接口；建议先统计重复请求和慢请求重叠，再集中调度。

## 本轮验证与复现方式

测试运行在一次性 Linux 容器和 `t.TempDir()` 中。仓库通过只读挂载提供源码，未使用本机业务数据库或任何真实凭据。额外核验脚本保存在被 git 忽略的 `.local/audit-verification/`，通过 Go `-overlay` 加入测试包，没有向正式源码写入测试副本。

| `go test -race -overlay … ./internal/gateway -run … -count=1 -v` | 通过；6 组核验及 DNS、MCP 授权、Cookie 隔离、登录限流、TCP 半关闭、WAF 等专项。 |

核验脚本故意断言某些缺陷仍可复现，例如虚构凭据未脱敏；“脚本通过”表示核验结论符合当前行为，不表示这些缺陷已经修复。证据日志为 `.local/audit-verification/go-verification.log`、`additional-verification.log`、`frontend-tests.log`。

按复现顺序重跑时，可使用现有 Go 构建镜像，以 `/src` 为只读仓库挂载点，再执行：

```sh
CGO_ENABLED=0 go test -overlay /src/.local/audit-verification/overlay.json ./... -count=1
CGO_ENABLED=1 go test -race -overlay /src/.local/audit-verification/overlay.json ./internal/gateway -run TestAuditVerification -count=1
CGO_ENABLED=1 go test -race ./internal/gateway -run 'Test(DDNSRecordsAreResolvedPerDomainAndFamily|DNSFailureDoesNotHideOtherFamily|DNSChecksAreBoundedAndNewDomainsHavePriority)$' -count=100
```

race 命令需要 Linux C 工具链；本轮只在一次性容器内安装 gcc/musl-dev。`.local` 脚本不随提交分发，如后续修复，应将对应缺陷转化为期望正确行为的正式回归测试。

- [Go 语言规范：变量](https://go.dev/ref/spec#Variables)：结构体字段可以分别寻址，各自视为变量；对应 OPT-3 的内存位置判断。
