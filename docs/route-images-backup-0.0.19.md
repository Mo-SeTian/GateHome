# 服务图片与备份覆盖 · 0.0.19

## 服务图片

在反向代理的「添加代理服务 / 编辑」弹窗中设置服务图片，支持三种来源：

- 上传 PNG、JPEG、GIF、WebP、ICO 文件。输入最大 5 MiB、位图最大 4096 × 4096，位图重新编码为最大 128 像素 PNG 并移除元数据；GIF 使用首帧；ICO 保留原格式，最大 64 KiB。
- 填写 HTTP / HTTPS 图片 URL，点击「获取图片」，或直接保存规则自动获取。服务器下载为本地文件，无需浏览器跨域访问；不记录源 URL。允许内网 NAS 地址，不发送登录 Cookie / 认证头，校验 HTTPS 证书，禁止 URL 内嵌账号密码及云元数据、链路本地地址。
- 在「发现内网服务」扫描结果中选择服务，勾选「采用应用图标」后创建规则。图标复制到永久图片存储，后续重新扫描不会让规则图片失效。

图片处理完显示预览，保存规则后列表、概览和防火墙代理列表使用该图片。移除恢复默认图标；取消编辑保留之前的图片。处理失败保留原图片并显示原因；关闭弹窗、重新编辑会忽略旧请求结果。图片文件由管理员会话保护，只接受本地内容哈希引用，不把外部 URL 直接写入页面。

只备份已保存规则引用的图片；重复图片按内容去重。取消编辑留下的暂存图片在后续导入时清理超过一天且未被任何规则引用的文件。

新备份格式为 `gatehouse-backup-v2`，旧版程序会明确拒绝，避免旧逻辑悄悄漏掉新文件。新版继续支持 `gatehouse-backup-v1` 旧备份。加密仍使用 AES-256-GCM + scrypt，密码至少 12 字节，密码不保存到配置或日志。检查备份时显示图片、证书文件、日志条数、订阅缓存数量与是否为完整文件备份。文件路径使用白名单，拒绝穿越目录、符号链接、损坏图片、无效日志或缓存、遗漏引用图片的备份。64 MiB 内容限制超出会报错，不静默截断。日志覆盖磁盘保留的数据，已经轮转清理的更早历史无法从当前备份恢复。

新备份恢复会替换四个业务目录：`certificates/`、`route-images/`、`logs/`、`subscriptions/`，最后原子写入 `state.json`。配置写入失败时回滚目录替换；新版启动器维护事务保存全部业务数据，新进程启动失败或恢复中断时恢复维护前数据和程序。密码和图片文件权限为 `0600`，目录为 `0700`。

旧备份继续支持，检查时明确提示缺失范围，恢复时保留现有日志、缓存和图片目录，不把它们当成旧备份中的数据。当前程序拒绝高版本备份，因此包含新图片引用的备份不能导入旧程序。

## 旧启动器升级

Web 更新无法更新只读启动器。0.0.18 及更早的 Linux 安装在首次完整恢复前，需进入 `版本/0.0.19` 执行 `sudo bash install.sh` 并选择安装，保留原数据。Docker 需重建新版镜像，保留数据卷。新版业务程序会检测启动器的完整文件恢复能力；缺少能力时检查页禁用恢复，直接 API 操作同样拒绝。

## 验证

自动测试覆盖位图 / WebP / ICO 解码与限制、内容哈希与去重、损坏 / 非法 / 路径输入、匿名访问与跨站写入拒绝、内网 URL 下载、TLS 验证、扫描图标永久保存、规则图片引用检查。完整备份测试在独立目录导出、解密、恢复并重新打开配置、图片、日志、订阅，同时验证写入失败和维护回滚；已有 DNS / 证书 / 密码测试验证各类凭据保护。

前端检查覆盖图片加载失败、关闭与重新编辑忽略旧响应、保存与扫描创建保留图片引用，以及原有域名校验、折叠、弹窗和减少动效行为。浏览器在隔离演示中验证上传、URL、扫描、取消编辑、桌面与手机布局。
